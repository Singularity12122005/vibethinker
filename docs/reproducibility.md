# 可复现性约定

## 最小可复现记录

每条可执行主线应提供：

1. 冻结的模型和数据版本或内容哈希；
2. 不含凭据的配置；
3. 数据行数、去重和污染审计摘要；
4. verifier 合同与 CPU 合同测试；
5. prompt、completion 和总上下文预算；
6. checkpoint 前缀、完成标记和恢复验证；
7. 冻结评测入口与聚合指标。

## 结果与运行状态分离

平台显示“成功”不代表产物已持久化；显示“运行中”也不代表已完成一次有效更新。
训练至少应完成 rollout、判分、旧策略/参考前向、反向、优化器更新、权重同步和下一轮
启动，才可称为健康启动。数据任务必须在退出前形成带完成标记的紧凑结果包。

## 重试与恢复

runtime 修复、OOM 调参、挂载修复和中断恢复均属于同一实验的 attempt。只有研究问题、
数据条件或核心算法发生足以改变归因的变化时，才创建新实验。无效 attempt 的 reward
和吞吐不得进入模型结论。

## 安全与发布

- 配置只保留可公开复现的逻辑参数；
- 不提交凭据、内部任务标识、组织信息、本机绝对路径或服务地址；
- 不提交 raw predictions、逐题判分、训练日志、checkpoint 或 optimizer state；
- 公开来源使用稳定网页链接，私有运行资产只记录内容合同，不记录内部标识。
