# 实验记录方法

## 记录单位

一条公开主线必须对应一个清楚的“数据 → SFT → RL”血缘。以下内容不创建新主线：

- 同一配置因调度、依赖、解析、显存或 runtime 缺陷而重试；
- 只改变打包版本而没有改变研究问题；
- 训练任务的恢复、续跑和 checkpoint 保存；
- 对同一实验从“进行中”更新到“完成”。

这些变化只在实验卡的工程边界或限制中简要说明。清洗、蒸馏、评测和基础设施修复
进入共享代码与工程文档，不包装成训练实验。

## 状态语义

实验卡描述当前可引用结果，而不是平台曾显示的任务状态。`completed` 只用于已经形成
训练、checkpoint 和冻结评测闭环的阶段；`partial` 表示只有中间 checkpoint 或部分
评测；`running` 只描述调度状态，若没有有效 step 证据必须同时注明健康性未确认。

## 结论强度

结论只能覆盖证据实际支持的范围。烟雾测试证明“链路可运行”，不能证明模型能力提升；
小样本首步指标不能推断长期训练；丢失逐题产物的任务不能标为完整数据资产；没有冻结
评测的配置只能标为计划或部分完成。

## 数据边界

台账只保存聚合结论、配置摘要和公开来源，不保存逐题输出、原始日志、模型产物或训练
数据。研究报告只摘录决策所需结论，并链接公开一手来源。
