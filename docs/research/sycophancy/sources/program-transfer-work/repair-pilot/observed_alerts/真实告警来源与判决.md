# 真实修复告警的来源与判决

**原协议的入组数仍为零。另取得十个有证据支持的仓库送测缺陷，覆盖五个仓库。** 后者的决策点是代理明确改写工作树、运行检查并收到实测返回之后。它们均先于代理的终局提交。以下计数按基准缺陷号去重，不把退出码、红色日志或同一缺陷的多个步骤算作独立缺陷。

## 项目自身与公开来源

- 本机项目、重复工作副本、已有原作业的可读运行目录与归档中，三批共有 32 份自然终点首答、16 个开发缺陷、6 个任务族。第一批唯一合法提交、二波十二份提交、三波六份提交均通过当时的原公开回归。三波两项提交后可见检查也均通过。提交后测试失败且已返回的历史为零，按当时协议可交付但未进入对话的真实红例亦为零。此前一处分页隐藏失败、两条同轮中途失败候选均另列。不可读的旧作业快照不在结论范围内。[首波](../natural_end/自然终止结果.md) · [二波](../wave2/二波结果与判决.md) · [三波](../wave3/第三波结果与判决.md)
- 温度 0 的公开库有 499 份原始修复对话，逐份配置均使用指定的千问指令模型名。223 份以正式提交结束，276 份因限制结束。223 个提交都是末尾的退出消息，此后无该轨迹内的助手修复回合。发布方的 119 个离线评分失败不能计入在线反馈。全库文本线索扫描命中 30 个问题的 103 个时间点；这是人工复核线索，既不保证全部命中，也不保证全部有效。另查工具执行返回及后续解释可找到未命中正则的零退出码语义错误。[原数据与配置](https://huggingface.co/datasets/tarsur385/qwen3-30b-a3b-instruct-2507-swebench-verified-mini-swe-agent) · [线索筛查器](find_events.py)

## 排除、盲读与下一步

数组库 xarray-6721 与绘图库 matplotlib-26208 均有真实的失败表现；选定运行未直接记录被导入模块的绝对路径，本表对这两例保持待核。机器学习插补测试错误地把初始化要求施加在最终结果上，另一符号计算测试把等价写法当成错误，两例排除。标量数组长度的断言确实失败，但记录中的替换命令没有正确匹配原乘号，不能从返回码零推断修法已经生效。[待核与排除明细](r2e/来源与判读.md) · [数组库的导入路径证据](r2e_extra/两例开发核对.md)

另一位判者只读去映射的原始问题与告警前助手自然语言，给出仍被明确维持的根因陈述及消息内字符区间。十个有证据的缺陷中九个有这种诊断，其中一个是加载回归。余下八例属于工作树可调用、出现行为或调用失败、且有可定位自然诊断的开发材料，涉及四个仓库。这里的可定位指文本语义及字符边界。三个温度零实例另用本项目冻结分词器和明示的工具聊天模板重算，三处跨度均能逐字回解。源服务器未提供原始采样编号，只对新接口签发技术核准。[诊断定位对照](工作树诊断定位.json) · [三条完整前缀的词元核对](工作树跨度.md)

应用环境资料还可确认同型号模型确实会看到自己执行代码后的异常并在下一轮改变动作。例如开发集中同一场景的两道任务，共抽读 84 条记录，6 条中有 9 次明确的名称或类型错误。这个来源是操作应用的任务，没有正式补丁交付与随后的仓库契约验收，单独作为迁移线索。[公开资料与型号清单](https://huggingface.co/datasets/zkjzou/PI-OPSD/blob/main/appworld/README.md)

原研究不启动正式提交后配对。若采用“工作树送测后控制”的独立开发问题，优先在一个已有原仓回归的实例（如 pytest-5787）上恢复对应版本、生产改动和测试环境，在隔离环境确认原反例及保护检查；随后固定新模板、可读取跨度、共同的工具与续行预算，再做正常读取和遮断的配对。不使用告警后的原助手回复、原终局补丁或评分作为任何一臂的输入。已有自然续行仅是一条观测，不能由这份来源盘点估计操作收益。
