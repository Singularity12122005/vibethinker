# goal-round 协议（与工具无关的研究回合规范，v3）

本文件定义一轮 `/goal` 研究回合**必须**做什么、各角色之间**只能**传递什么、什么时候**不得**提交。它不依赖任何特定的编排工具：
`.claude/workflows/goal-round.js` 是它的一个执行器；没有该工具的环境（例如没有 Workflow 工具的 Windows 环境）按 §6 用普通代理逐阶段执行同一协议，结果等价。

## 1. 设计原则（来自 r1–r3 的失败模式）

| 失败模式（已发生） | 机制 |
| --- | --- |
| 综合时夸大（r1 的 13 条；r3 之后的"不存在闭式""128 条只对二次"） | 每条主张自带 **scope**（成立条件）与 **does-not-claim**（它不建立的最近更强陈述）；综合必须逐字复制；最终报告过一道"越界审查"，列出每句强于其支撑主张的话并给出可支撑版本 |
| 前提不满足却套用恒等式（P6） | 前提作为可核对项写入 assumptions；"实验范围"视角逐条对照真实管线检查前提 |
| 问题本身提错（四标量） | "问题批判"阶段先填障碍模板（§2），列出目标量真正依赖的量，陈述缺的就重写 |
| 生成与验证之间信息泄漏（盲重实现未强制） | 盲重实现只拿到陈述、假设、scope、数字；只能写自己的目录；必须列出读过的每个文件；脚本审计 `files_read`，发现本轮其他目录即撤销"盲"资格 |
| 证据丢失（按路线顺序取前三、过滤作者自驳、修复结果未返回） | **完整台账**：每条主张都有台账状态（reviewed / unreviewed_overflow / author_refuted）；审查名额按路线轮转；未审与作者自驳必须交接并在记录中标明；返回值以修复后状态与最终检查为准，检查未过则 **blocked，不得提交** |
| 来源混淆（旧环境 4.57.1 与新环境 5.20.1 的数据被混写） | 每个数字带来源文件与环境标签；检查器核对 |
| 输入与目标错位（用 h_2 计数回答 h_3 的问题） | 模板要求写明输入数据的**产生机制**，并与设计的筛选规则对照 |
| 范围蔓延 | 每轮一个障碍；审查名额 ≤3；相邻问题只有能改变决策时才扩展 |

## 2. 障碍陈述模板（问题批判阶段必须填满）

- **决策**：答案会改变哪个实验决策（预算、判据、门控）。
- **输入与其产生机制**：会消费哪些数据，它们是怎么产生的，是否与设计的筛选规则一致（例：G6 的对象是按 §7.11 规则筛出的第三轮前缀 $h_3$，不是 $h_2$）。
- **模型类 / 相容集**：允许的模型或与预试验数据相容的分布集合，以及这个集合由什么识别、识别到什么阶。
- **要证明的性质与量词**："对相容集内所有……""存在……使得……"。
- **成功 / 失败判据**：什么结果算解决，什么结果算不可判定。
- **范围外**：明确不在本轮之内的相邻问题。

示例（r4，用户确认版）：在与 G6 相同的第三轮前缀筛选机制下，明确端点响应模型，研究与预试验计数相容的风险分布范围，能否把二次校正检验的假阳性率和区间宽度约束得足够紧，从而决定每前缀 128 条续写是否值得采用。

## 3. 阶段、角色与交接物

| 阶段 | 角色（每个都是**新的空白上下文**） | 只接收 | 产出（JSON） |
| --- | --- | --- | --- |
| 问题 | 问题代理 ×1 | 档案 §1/3/5/7/9、规格书 §7.11、模块、本协议 §2、拟议障碍 | 模板六项、良定判断与批判、隐含依赖、闭式是否可信、≤3 条独立路线、不得重复的结果 |
| 攻击 | 攻击代理 ×路线数 | 模板、本路线、约束、不得重复清单（不看其他路线） | ≤3 条主张：陈述、状态、假设、scope、does-not-claim、推导、证据、脚本路径、数字（各带来源）、实验后果；what_failed、next_step |
| 台账 | 编排者（脚本或人） | 全部攻击产出 | 每条主张的台账状态：reviewed / unreviewed_overflow / author_refuted（名额按路线轮转，proved 优先） |
| 反驳 | 每条 reviewed 主张 3 个审查代理 | 数学视角：陈述+推导+脚本；**盲重实现**：仅陈述、假设、scope、数字；实验范围：陈述+后果+scope | refuted、severity（none/overstated/gap/wrong/irrelevant）、理由、修法、最强攻击、reproduced_numbers、**files_read** |
| 综合 | 综合代理 ×1 | 模板、攻击结果、**完整台账**（含未审与作者自驳及其证据） | §9 记录（A–F）、§7 更新、测试、manifest、待用户决定、计划变更 |
| 检查 | 越界审查 ×1 + 标签检查 ×1（修复后各再一次） | 报告与台账 / 仓库 diff | 越界句子清单；ok 与问题清单 |
| 修复 | 修复代理 ×1（最多一次） | 问题清单 | **修复后的**报告、决定、计划变更（返回值必须用它） |

**裁决规则**（编排者机械执行，不得由代理自裁）：
- 任一视角 `wrong` ⇒ refuted；任一视角 overstated/gap/irrelevant ⇒ candidate；三视角齐全且无驳回且盲重实现 `reproduced_numbers=true` 且审计通过 ⇒ 保留作者状态并记 **独立复核**；否则 candidate。
- 盲重实现审计：`files_read` 中出现本轮目录下非自身目录的任何文件 ⇒ 审计失败 ⇒ 不得记独立复核，记录中写"盲重实现未确认（隔离审计失败）"。
- 检查未通过或越界清单非空 ⇒ 一次修复 ⇒ 复检；仍不过 ⇒ 状态 **blocked**：不提交、不推送，把问题清单交给用户。

## 4. 记录与标签规则

- 状态只有五种：已证明（推导 + 可运行检验）、自检、独立复核、候选、已淘汰；"未审""作者自驳"是台账状态，不是研究状态。
- 每个数字：值、来源脚本/输出文件、环境（版本、硬件）、日期。
- 报告中不得出现比支撑主张更强的句子；全称否定（"不存在""不可能""只对……成立"）需要同量词的已证明主张。
- 连续两轮无实质进展：回到障碍模板重写问题，而不是换路线再攻。

## 5. 验收标准（提交前）

1. §9 新记录含模板六项、台账全体条目及状态、每条主张的 scope 与 does-not-claim 原文、数字来源。
2. 每条"已证明"有测试且通过；全套 `pytest -q` 通过。
3. diff 只触及档案、`tests/test_analysis.py`、`analysis/g6_iv.py`（本轮临时文件在仓库外）。
4. 越界清单为空；标签检查 ok。
5. 记录列出"待用户决定"与"实验计划变更（或无）"。

## 6. 无工作流工具时的手工执行（例如 Windows 环境）

1. 为本轮建目录 `goal_rounds/<round>/`，把拟议障碍写入 `obstacle.md`。
2. 逐阶段开**新的**代理会话，只粘贴 §3 规定的输入，要求按对应 JSON 结构返回；把返回保存为 `problem.json`、`attack_<route>.json`、`verdict_<id>_<lens>.json`、`synth.json`、`overreach.json`、`check.json`、`repair.json`。
3. 台账与裁决按 §3 的规则手工（或用一个小脚本）执行；盲重实现的会话中不得粘贴推导与脚本，并要求它列出读过的文件。
4. 修复后的 `repair.json` 是最终结果；`check.json` 未通过时不提交。
5. 路径以本机为准（根目录、python、临时目录都是参数，不写死）。
