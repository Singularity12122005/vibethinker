# goal-round 协议（与工具无关的研究回合规范；基础版 v3，现行 v5.1）

> **优先次序：** §1–§6 是 v3 基础版；§7（v4）、§8（v5）、§9（v5.1）是修订，冲突时以编号靠后的修订为准（例如 §3 的"一次修复"已由 §7.2 改为至多 3 次，§3 的三视角裁决已由 §8.2 改为真伪只由两个真伪视角决定）。

本文件定义一轮 `/goal` 研究回合**必须**做什么、各角色之间**只能**传递什么、什么时候**不得**提交。它不依赖任何特定的编排工具：
`.claude/workflows/goal-round.js` 是它的一个执行器；没有该工具的环境（例如没有 Workflow 工具的 Windows 环境）按 §6 用普通代理逐阶段执行同一协议，机械部分照样用 `round_gate.py` 与 `verify_evidence.py`（§9），结果等价。

## 1. 设计原则（来自 r1–r3 的失败模式）

| 失败模式（已发生） | 机制 |
| --- | --- |
| 综合时夸大（r1 的 13 条；r3 之后的"不存在闭式""128 条只对二次"） | 每条主张自带 **scope**（成立条件）与 **does-not-claim**（它不建立的最近更强陈述）；综合必须逐字复制；最终报告过一道"越界审查"，列出每句强于其支撑主张的话并给出可支撑版本 |
| 前提不满足却套用恒等式（P6） | 前提作为可核对项写入 assumptions；"实验范围"视角逐条对照真实管线检查前提 |
| 问题本身提错（四标量） | "问题批判"阶段先填障碍模板（§2），列出目标量真正依赖的量，陈述缺的就重写 |
| 生成与验证之间信息泄漏（盲重实现未强制） | 盲重实现只拿到陈述、假设、scope、数字；只能写自己的目录；必须列出读过的每个文件；脚本审计 `files_read`，发现本轮其他目录即撤销"盲"资格 |
| 证据丢失（按路线顺序取前三、过滤作者自驳、修复结果未返回） | **完整台账**：每条主张都有台账状态（reviewed / unreviewed_overflow / author_refuted）；审查名额按路线轮转；未审与作者自驳必须交接并在记录中标明；返回值以修复后状态与最终检查为准，检查未过则 **blocked，不得提交** |
| 来源混淆（旧环境 4.57.1 与新环境 5.20.1 的数据被混写） | 每个数字带来源文件与环境标签；检查器核对 |
| 输入与目标错位（用 h_2 计数回答 h_3 的问题） | 模板要求写明输入数据的**产生机制**，并与设计的筛选规则对照 |
| 范围蔓延 | 每轮一个障碍；审查名额 ≤3；相邻问题只有能改变决策时才扩展 |

## 2. 障碍陈述模板（问题批判阶段必须填满）

- **决策**：答案会改变哪个实验决策（预算、判据、门控）。
- **输入与其产生机制**：会消费哪些数据，它们是怎么产生的，是否与设计的筛选规则一致（例：G6 的对象是按 §7.11 规则筛出的第三轮前缀 $h_3$，不是 $h_2$）。
- **模型类 / 相容集**：允许的模型或与预试验数据相容的分布集合，以及这个集合由什么识别、识别到什么阶。
- **要证明的性质与量词**："对相容集内所有……""存在……使得……"。
- **成功 / 失败判据**：什么结果算解决，什么结果算不可判定。
- **范围外**：明确不在本轮之内的相邻问题。

示例（r4，用户确认版）：在与 G6 相同的第三轮前缀筛选机制下，明确端点响应模型，研究与预试验计数相容的风险分布范围，能否把二次校正检验的假阳性率和区间宽度约束得足够紧，从而决定每前缀 128 条续写是否值得采用。

## 3. 阶段、角色与交接物

| 阶段 | 角色（每个都是**新的空白上下文**） | 只接收 | 产出（JSON） |
| --- | --- | --- | --- |
| 问题 | 问题代理 ×1 | 档案 §1/3/5/7/9、规格书 §7.11、模块、本协议 §2、拟议障碍 | 模板六项、良定判断与批判、隐含依赖、闭式是否可信、≤3 条独立路线、不得重复的结果 |
| 攻击 | 攻击代理 ×路线数 | 模板、本路线、约束、不得重复清单（不看其他路线） | ≤3 条主张：陈述、状态、假设、scope、does-not-claim、推导、证据、脚本路径、数字（各带来源）、实验后果；what_failed、next_step |
| 台账 | 编排者（脚本或人） | 全部攻击产出 | 每条主张的台账状态：reviewed / unreviewed_overflow / author_refuted（名额按路线轮转，proved 优先） |
| 反驳 | 每条 reviewed 主张 3 个审查代理 | 数学视角：陈述+推导+脚本；**盲重实现**：仅陈述、假设、scope、数字；实验范围：陈述+后果+scope | refuted、severity（none/overstated/gap/wrong/irrelevant）、理由、修法、最强攻击、reproduced_numbers、**files_read** |
| 综合 | 综合代理 ×1 | 模板、攻击结果、**完整台账**（含未审与作者自驳及其证据） | §9 记录（A–F）、§7 更新、测试、manifest、待用户决定、计划变更 |
| 检查 | 越界审查 ×1 + 标签检查 ×1（修复后各再一次） | 报告与台账 / 仓库 diff | 越界句子清单；ok 与问题清单 |
| 修复 | 修复代理 ×1（最多一次） | 问题清单 | **修复后的**报告、决定、计划变更（返回值必须用它） |

**裁决规则**（编排者机械执行，不得由代理自裁）：
- 任一视角 `wrong` ⇒ refuted；任一视角 overstated/gap/irrelevant ⇒ candidate；三视角齐全且无驳回且盲重实现 `reproduced_numbers=true` 且审计通过 ⇒ 保留作者状态并记 **独立复核**；否则 candidate。
- 盲重实现审计：`files_read` 中出现本轮目录下非自身目录的任何文件 ⇒ 审计失败 ⇒ 不得记独立复核，记录中写"盲重实现未确认（隔离审计失败）"。
- 检查未通过或越界清单非空 ⇒ 一次修复 ⇒ 复检；仍不过 ⇒ 状态 **blocked**：不提交、不推送，把问题清单交给用户。

## 4. 记录与标签规则

- 状态只有五种：已证明（推导 + 可运行检验）、自检、独立复核、候选、已淘汰；"未审""作者自驳"是台账状态，不是研究状态。
- 每个数字：值、来源脚本/输出文件、环境（版本、硬件）、日期。
- 报告中不得出现比支撑主张更强的句子；全称否定（"不存在""不可能""只对……成立"）需要同量词的已证明主张。
- 连续两轮无实质进展：回到障碍模板重写问题，而不是换路线再攻。

## 5. 验收标准（提交前）

1. §9 新记录含模板六项、台账全体条目及状态、每条主张的 scope 与 does-not-claim 原文、数字来源。
2. 每条"已证明"有测试且通过；全套 `pytest -q` 通过。
3. diff 只触及档案、`tests/test_analysis.py`、`analysis/g6_iv.py`（本轮临时文件在仓库外）。
4. 越界清单为空；标签检查 ok。
5. 记录列出"待用户决定"与"实验计划变更（或无）"。

## 6. 无工作流工具时的手工执行（例如 Windows 环境）

1. 为本轮建目录 `goal_rounds/<round>/`，把拟议障碍写入 `obstacle.md`。
2. 逐阶段开**新的**代理会话，只粘贴 §3 规定的输入，要求按对应 JSON 结构返回；把返回保存为 `problem.json`、`attack_<route>.json`、`verdict_<id>_<lens>.json`、`synth.json`、`overreach.json`、`check.json`、`repair.json`。
3. 台账与裁决按 §3 的规则手工（或用一个小脚本）执行；盲重实现的会话中不得粘贴推导与脚本，并要求它列出读过的文件。
4. 修复后的 `repair.json` 是最终结果；`check.json` 未通过时不提交。
5. 路径以本机为准（根目录、python、临时目录都是参数，不写死）。

## 7. v4 修订（2026-10-20，r4 的教训）

r4 在协议 v3 下：单次修复后仍 blocked；编排者随后做了 3 次"修复 → 9 个独立审计"的扩展循环，问题数 85 → 48 → 28，没有收敛，记录从 119k 涨到 168k 字符。失败的原因是结构性的：几百个数字写在正文里，每个数字都是可审计的负债；随机的审计代理在 5 万字的记录上总能找到新的小问题；而引用的源文件在会话临时目录里，会话结束就无法复核。v4 的改动：

1. **三层记录。** (a) 档案 §9 的回合记录只写：障碍模板（简写）、台账表（编号、状态、一句话陈述、scope、does-not-claim）、每条主张 ≤5 个**头条数字**（以证据编号引用）、待用户决定、计划变更、下一轮攻击；§9 回合小节以约 12000 字符为上限。(b) **证据表** `docs/research/goal-rounds/<round>/evidence.json`：每个头条数字一条，含打印值、种类（point / upper / lower / exact / count）、仓库内源文件、定位（JSON 路径或正则）、条件；由 `.claude/skills/goal/verify_evidence.py` **机械核对**数值与取整方向（上界向上、下界向下、点估计就近）。(c) **完整工作材料**（脚本、输出、详细记录、审查判词与台账）复制进 `docs/research/goal-rounds/<round>/`（不含大型二进制数组），标为工作材料，不逐句审计。
2. **严重度分级。** 阻断：标签高于判词；陈述强于台账（越界）；头条主张漏了条件；证据核对失败；测试失败。非阻断：详细记录中的引用位置、格式、措辞。闸门 = 零阻断 + 核对器通过 + 测试通过；非阻断问题逐条记入详细记录末尾，不卡提交。修复循环最多 3 次。
3. **收窄陈述重审。** 三个视角都确认了数学核心、只是后果或范围措辞过头的主张，可以按审查者给出的修正文字收窄；收窄后的陈述必须由**新的**三视角重新审查，按 §3 的机械规则重新裁决——不得只改措辞就升级标签。
4. **攻击代理不得在自己的计算仍在运行时返回**；未完成计算的数字不得进入主张（r4 的 A-C2 汇总与 C3 第二阶段即属此类，记为待完成）。
5. **盲重实现的隔离范围**扩大到仓库内的 `docs/research/goal-rounds/<round>/` 证据目录与审查判词。
6. **断点续跑。** 工作流中途因额度或进程重启中断时，用同一脚本与参数续跑（已完成的代理从缓存回放）；续跑本身记入记录。

## 8. v5 修订（2026-10-20，r4 收尾的教训）

r4 按 v4 收尾时，A-C1、B1、C1 的收窄陈述与 B2-core 经新的三视角重审后仍全部是候选，而它们的数学核心在两轮、六个以上独立实现中被反复确认。原因又是结构性的：每条送审陈述把前提、结论、后果与注意事项打包成几百词，每个视角总能挑出其中一句。v5 的改动：

1. **原子主张。** 送审的每条主张是单一命题：一个定理或恒等式、一组数值、或一条代码接口事实。后果与对实验的含义不写进主张，另写为**适用性注记**。
2. **真伪与适用性分离。** 真伪标签只由数学视角与盲重实现决定：两者都未驳回且严重度为 none，盲重实现复现了数字（无数字时须在自造的有限例上精确验证），隔离审计通过 ⇒ **独立复核**；任一为 wrong ⇒ **已驳回**；否则 **候选**。适用性视角的判词（none / gap / irrelevant，并列出在真实设计中不成立或可能不成立的前提）写成适用性注记，不改真伪标签。该规则在任何原子判词出现之前宣布并一致适用；台账同时保留 v3/v4 规则下长陈述的标签。
3. **修正后重审。** 被驳回或被指出缺口的原子，只能按审查者的修正文字改写，并交给**新的**三视角重审；每个版本的原文与判词都入档（`atoms/atom-statements.json`、`atoms/atomic-review-verdicts.json`），不覆盖。
4. **代码事实靠代码保证。** 关于生产代码的命题若在边界情形上反复失败（r4 的 B2 前三个版本：误形状输入的广播、警告当错误、不可转换的输入），就改代码，使性质成为接口事实（r4：`corrected_moment_matrix` 不接受结局参数，`endpoint_contrast_poly_cs` 在任何结局运算之前取得正定判定），以测试锁定，陈述随之缩成接口陈述。
5. **编排者起草的原子同样送审。** r4 中编排者起草的原子有两处错误：B1 的达成规则把不等号方向写反（该规则给出 1+TV），A-C1 的矩阶数从句对任意 $\sigma^2(r)$ 过宽。两处都由两个真伪视角独立发现。起草者不因身份豁免审查。
6. **数量与执行器约定（v5 执行器 `goal-round.js`）。** 每条路线至多 6 条原子主张；审查名额默认 3、至多 6（参数 `max_claims`）。主张编号由编排脚本分配（`R<路线>-<序号>`），作者编号另存，避免跨路线重名。每个代理把自己返回的 JSON 写进自己的目录（问题、攻击、每个视角的判词、改写），复制进仓库后即为持久判词，不靠代理转录。数字若来自攻击者列出的未完成计算，主张记为"排除"，不送审。机械闸门由脚本检查核对器与 pytest 输出的末两行（全部条目通过、无失败）和回合小节的字符数（上限约 12000）。修复至多 3 次；缺席的审计代理重试一次，仍缺席即 blocked。闸门通过后，非阻断问题逐条写入详细记录。盲重实现的隔离审计只接受绝对、规范化的路径，相对路径、`~`、`..` 一律算作越界，空的 `files_read` 不通过；禁区包括本轮临时目录、仓库内各轮证据目录、工作流转录与工作流结果文件。证据表的源路径必须相对仓库根目录，核对器拒绝绝对路径。

## 9. v5.1 修订（2026-10-20，执行器 `goal-round.js` 三轮独立审查的教训）

v5 执行器经四轮独立审查（运行时视角、协议视角、闸门工具视角、诚实代理可达性视角，各自用桩代理实际运行脚本并给出复现）找出的缺陷，大多属于同一类：本应由代码保证的事实交给了代理转述或自由文本匹配。v5.1 的原则是：**能机械测量的都由 `.claude/skills/goal/round_gate.py` 测量，由脚本判定；代理只负责运行给定命令并原样返回末行；脚本要求每个所请求的测量都完整出现，缺一项即阻断；参照值（基线、期望的模块与测试哈希、冻结哈希）由 `round_gate.py` 写在状态目录里并自己比较，脚本只看比较结果（布尔值），从不比较由代理抄写的哈希串。**

1. **基线由代码测量并存档。** 回合开始时 `round_gate.py --only baseline,pytest,hashes,fresh --state-dir <临时根>/<轮次>.state` 把 HEAD、工作树中每个已改动路径的内容哈希与暂存区（index）中的 blob 写进该目录的 `baseline.json`，把模块与测试文件的哈希写进 `expect.json`（都不经代理转述，也不进仓库）；同时记下全套测试的通过数。范围检查读取 `baseline.json`，然后：允许文件（档案、`tests/test_analysis.py`、模块、本轮证据目录）之外的改动路径若不在基线中、或在基线中但工作树内容或暂存内容变了（例如代理执行了 `git add -A`），即阻断；基线路径即使已不在 `git status` 中（被还原、被提交、被删除），内容或暂存 blob 变了也阻断；HEAD 移动（回合中有人提交）即阻断。`git status` 用 `--porcelain=v2 -z` 解析（重命名的两侧都计入）。通过的测试数少于基线即阻断（基线必须有 pytest 汇总，否则重试一次后 blocked）。被 git 忽略的路径不在范围检查之内（已知局限）。**轮次名不得复用**：基线测量同时报告本轮临时目录与证据目录是否已有内容；新的一次运行发现它们非空即 blocked（换新的轮次名，或先把旧目录移开）；续跑时这一测量从缓存回放，不受影响。
2. **隔离审计的路径规则。** 只接受绝对、规范化的路径：相对路径、`~`、任何 `.` 或 `..` 段、`//`、控制字符与格式字符（含 U+FEFF、U+2028/2029、零宽字符）一律越界，先于"自身目录"判断；首尾只去掉空格、制表、回车、换行；字符类别按 Unicode 判定（Cc、Cf、Zl、Zp）。禁区按前缀与子串判定：整个临时根目录（含前几轮）、仓库内各轮证据目录与任何检出中的 `docs/research/goal-rounds/`、档案本身、会话转录（`/.claude/projects/`、`/subagents/`）、持久化的工具输出（`/tool-results/`）与所有任务输出文件（`tasks/*.output`）。盲重实现被要求把长输出重定向进自己的目录。同一规则在 `goal-round.js` 与 `round_gate.py` 中各实现一次，桩测试在刁钻输入上逐一核对两者相同。
3. **盲重实现状态三分；过程失败重跑一次。** `ok` / `audit_failed` / `missing`：只有 `audit_failed` 写"盲重实现未确认（隔离审计失败）"，`missing` 写"盲重实现缺席"。**过程失败**（某视角缺席；隔离审计失败而该判词本身是干净的——未驳回、严重度 none、复现了数字；缺席的适用性视角）允许在同一文本上重跑一次，而且只在重跑可能改变结果时才重跑（已有实质性否定判词时只重跑缺席的适用性视角）；最后一个修正轮之后还有一次专门的过程重跑，所以改写版本与过期重审中的过程失败同样得到这一次机会（新的尝试编号 `a<k>`，其余视角的判词保留）；**实质结果**（未复现数字、发现缺口、判为 wrong）不重跑，即使同一判词的隔离审计失败——越界只能虚增一致，不能成为丢弃否定结果的理由；重跑直到通过就是挑判词。
4. **改写的合法性由脚本比对。** 只有声明了 `code` 字段的变更才算代码变更请求（`code_change` 中的其他文字一律忽略）。改写后的主张逐字段（陈述、前提、数字、种类、does-not-claim、后果）与原文比较：任何改动都必须有对应字段的变更条目；陈述、前提、数字、种类只能依据数学或盲重实现的修正文字；什么都没改的"改写"被拒绝；新数字必须来自路线或改写目录下的已完成输出，不得来自该路线列为未完成的计算；`uses_module` 只能由假变真。作者编号、路线固定不变。被拒绝的改写连同理由入档（`gave_up`）。
5. **代码事实路线：备份、测试与回滚都是机械的。** 模块与测试文件的**期望哈希**记在状态目录的 `expect.json`（基线写入；每次被接受的代码变更后由 `--only accept` 改写）。每次代码变更前，`round_gate.py --only backup` 把两者复制进本轮临时目录（已有副本时不覆盖）并报告备份与当前文件是否等于期望值；不等（有人在代码变更之外改了模块，或沿用了别的运行的备份）即 blocked。代码代理的**第一步**是运行给定的 `--only restore` 命令并原样返回其末行——续跑时被中断的代码代理是第一个实时运行的调用，这样半改的文件总会先被恢复；该行未显示恢复到期望值，修改就不被接受。随后 `--only hashes,pytest` 机械地确认模块相对期望值确实变了、测试全部通过、通过数不少于基线，接受后 `--only accept` 记下新的期望值；否则 `--only restore` 从备份恢复并核对恢复后的文件等于期望值，恢复失败（重试一次后）即 blocked。写记录前的模块快照也必须等于期望值。每次成功的代码变更使"代码纪元"加一；每条判词记下它作出时的纪元，一个判定的纪元取其各视角判词纪元的最小值。关于模块的主张（`code_fact` 或 `uses_module`）：已记独立复核且判定纪元早于当前纪元的，在同一修正轮里按原文全部重审（`stale_after_code_change`）；过程失败重跑时，若保留的判词早于当前纪元，改为三视角全部重跑。审查之后模块只允许新增：写记录前对模块做快照，闸门按语法树逐条比较快照中的顶层语句（装饰器在内；语句间的注释与排版不计），快照语句缺失或改变、新增语句不是新的导入、函数或类（装饰器只允许 `@dataclass`）、新增语句重新绑定受保护的名字（快照在模块层绑定或读取的名字，以及快照中的函数按符号表解析为全局的名字——包括被审查代码用到的内置函数，例如 `from numpy import max`；函数的局部变量不算），或新增代码含有改变他处的写法（导入时求值的位置——装饰器、默认值、注解、基类、类体——中的动态命名空间访问或对受保护名字的属性、下标赋值；函数体中对受保护名字的 `global`/`nonlocal` 声明、动态命名空间访问、或对按符号表解析为全局的受保护名字的属性、下标赋值），都是阻断。
6. **持久判词与台账由代码核对。** 写记录前，`round_gate.py --only copy,snapshot` 把本轮临时目录的文本文件（按内容判定：无 NUL 字节且是合法 UTF-8；无论扩展名）复制进证据目录（布局不变，跳过 >5 MB 的文件，写 `PATHS.md`），并报告被 git 忽略的已复制文件的完整清单——调用者提交时须对它们用 `git add -f`；文件名不是合法 UTF-8 的文件不复制，列在 `PATHS.md` 中。台账中来自代理的对象（数字、变更、未完成计算）只保留其 schema 字段，因此台账里没有非整数的数值，两侧的规范化 JSON 一致。台账由脚本构造，按**小块**交给代理：每个顶层键一个文件、每个版本一个文件（`review-verdicts/ledger.parts/<键>.json`，每块至多几千字符）；判词的长篇理由不进台账（它们在冻结的 `review/*/verdict.json` 中，写记录代理从提示中直接得到），未审主张只记编号、状态、截短的陈述与指向 `route<k>/attack.json` 的指针。`--only assemble,ledger,freeze` 按清单顺序把各块拼成 `review-verdicts/ledger.json`，比较其规范化 sha256（ASCII 转义的紧凑 JSON）与脚本自己算出的值——任何字段的改动都会被发现——并逐块比较，报告不一致的块，重试时只重写这些块；再按与脚本相同的规则从判词关键字段重算每个版本的标签并与 `--expect` 比较；最后把冻结哈希记进状态目录的 `frozen.json`；审查者自己写的 `verdict.json` 副本与台账不一致只记为非阻断警告。复制进来的工作材料与台账（`problem/`、`route<k>/`、`review/`、`rewrite/`、`code/`、`review-verdicts/`）的冻结哈希以 `frozen.json` 为参照；之后任何一次闸门报告与参照不同即阻断——写记录与修复都不得改动它们。
7. **证据表。** 源文件只能是冻结的工作材料中的普通文件（`problem/`、`route<k>/`、`review/`、`rewrite/`、`code/` 之下；不经符号链接，不在 `__pycache__` 中；冻结哈希把符号链接也作为条目计入），写记录代理自己新建的文件不能作为来源；条目若写明 `claim` 与 `number`，其 `kind` 必须与台账中该数字的种类一致（上界或下界不能记为 point）；`verify_evidence.py` 的 `--under` 可重复给出；`--require-environment` 要求每条带环境；`printed` 必须是 JSON 字符串；`count` 要求打印值与源值都是整数；JSON 定位走进非容器节点时报错而不中断。闸门逐个检查记录中的 `[E:<id>]` 标签：编号存在，且打印值以完整数字出现在上一个标签与本标签之间（至多 120 字符）：前面不接数字、小数点或千位逗号，无符号的打印值前面不接正负号（数字、字母或括号后的减号是运算符，例如 1-0.52），后面不接数字、小数或千位延续、指数或 ×10；两侧都有反引号的标签（代码片段）视为提及。审查过的主张带数字而证据表为空 ⇒ 阻断。r4 的证据表早于本条，不带环境字段。
8. **记录。** §9 回合小节目标 12000 字符、机械上限 13000，从标题行量到下一个回合标题（`### r<数字>…`）或下一个 `## ` 标题；小节内部的子标题只能用 `####` 或更深，内部出现 `##`/`###` 标题即阻断；标题必须恰好出现一次（写记录与修复都是"替换已有、否则新增"，续跑不会重复追加）。写记录代理直接收到模板六项、原障碍与批判；已审主张的 scope 与 does-not-claim 从台账逐字复制，由检查代理比对。每条路线至多 6 条原子主张，多出的记为 `dropped_over_cap`；数字来源不在本路线目录下的主张记为"排除（数字无来源）"；攻击者以绝对输出路径列出未完成计算：给了输出路径时只按完整路径匹配排除；没给时按文件名（路径中或描述中的完整文件名记号）匹配。攻击提示要求未完成输出不与所引来源同名、描述中不点已完成文件的名。pytest 的计数取 pytest 自己写在仓库外状态目录中的 junit 报告（测试打印什么都不能改变计数；没有状态目录时取标准输出中最后一个汇总行），找不到报告或汇总行即阻断。
9. **出口。** 每个出口（包括早退）返回同一形状的全部状态：障碍与模板、攻击结果、台账、每个版本的标签、改写放弃清单、代码变更、记录、被 git 忽略的证据文件、每次闸门的阻断清单与全部非阻断问题、`reason`。blocked 的返回总带着阻断清单。各轮的非阻断问题都写入详细记录；写入之后机械闸门再跑一次（这是最后一次改动），失败即 blocked；写入失败时轮次仍可提交，但返回 `minor_issues_logged: false`，由调用者补记。返回值带着完整的闸门命令（`gate_command`）与状态目录，调用者可以原样重跑。
10. **续跑。** 续跑时唯一允许新增的参数是 `resume_note`：它只出现在台账步骤与写记录的提示中，因此此前所有代理调用都从缓存回放，台账步骤（复制、快照、拼装、冻结都是幂等的）及其后的步骤实时重跑。基线文件、参照文件与备份留在临时根目录下，续跑时沿用。
11. **验证执行器本身。** 执行器的改动须通过桩测试（真实脚本 + 假代理，覆盖每条出口、每条裁决分支与上述每条机械检查，并在刁钻输入上核对脚本与 `round_gate.py` 的规则相同）与 `round_gate.py` 的端到端测试（临时 git 仓库中逐项篡改并确认被发现）。在仓库根目录运行：`PYTHON=<带 numpy 与 pytest 的 python> node .claude/skills/goal/tests/tests.mjs` 与 `<python> .claude/skills/goal/tests/gate_e2e.py`；`<python> .claude/skills/goal/verify_evidence.py --selftest`。
12. **威胁模型。** 机械检查针对的是诚实但会出错的代理：疏忽、走捷径、续跑中断、顺手的 `git add -A`、符号与指数的抄写错误。它们不是沙箱：在 Python 这样的动态语言里，蓄意规避（例如在新函数的默认参数里经由别名修改他处状态）总能找到检查之外的写法。蓄意规避由越界审查与检查代理、以及调用者自己的复核（SKILL 第 5 步）兜底；发现时按 blocked 处理。
